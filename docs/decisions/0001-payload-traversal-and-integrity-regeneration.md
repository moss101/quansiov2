# 35 — Architecture decision record

```text
Decision ID: ADR-0001
Owner: governance
Status: ACCEPTED
Context: The sealed authority package predates git adoption of the
repository. Integrity tooling traversed the raw filesystem, so `.git/**`
objects, `.gitignore` and later `.venv/**` dependency trees entered manifest
coverage comparisons and validator term scans; integrity validation failed
on any committed checkout and would never be deterministic.
Problem: Integrity and authority validators must cover exactly the authority
payload on a git-hosted working repository, deterministically, without
scanning VCS internals, caches, dependency trees or validator self-tests.
Decision: Introduce `tools/governance/repo_paths.py` as the single payload
traversal ruleset (RULESET_VERSION tracked) used by `finalize_package.py`,
`validate_integrity.py`, `validate_authority.py` and the placeholder
scanner. VCS internals, caches, venvs, dependency trees and build outputs
are never payload. The placeholder scanner accepts only reason-class-checked
exclusions (`self_test`, `fixture`, `vendor`, `generated`) registered in
`scripts/scan_exclusions.json`. Integrity artifacts are regenerated by
tooling only, never hand-edited.
Alternatives considered: Hand-strip `.git` per operation (fragile,
non-reproducible); per-validator ad-hoc traversal (three implementations
would drift); moving self-test markers out of the validator (weakens the
authority's own adversarial coverage).
Affected architectural invariants: none weakened; GOV-004 determinism and
GOV-005 production-tree scoping are strengthened. Canonical tasks,
requirements, schemas and dependency edges unchanged.
Affected canonical owners/schemas/wiring: governance tooling only;
`generated`, `evidence`, `tools` path classes registered in the ownership
registry.
Threat/privacy/tenant impact: Reduces false positives that normalize scan
failures; prevents derived/vendor trees from masking missing production
coverage; the seal binds an exact reproducible payload.
Data migration/compatibility impact: Manifest, checksums and seal
regenerated once by `finalize_package.py`; no schema or registry semantics
changed.
Rollback/reversal plan: Revert `tools/governance/repo_paths.py` and the two
validator scripts, rerun `scripts/finalize_package.py`.
Testing/qualification impact: Covered by the GOV-001 acceptance suite and
authority self-tests running on every verification run.
Review trigger/date: Any packaging layout change, new derived directory, or
CI build isolation work (doc 50); review 2026-12-10.
```
